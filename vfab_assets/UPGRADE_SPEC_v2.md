# 1. 경쟁 분석 — 우리가 있는 자리

## 1-1. 기존 제품은 모두 「절차 훈련」이다

| 제품 | 기관 | 가르치는 것 | 대상 | 기술 |
|---|---|---|---|---|
| Microfab Game | UC Davis | 클린룸 입실 절차, 포토마스크 정렬 퍼즐 | 클린룸 투입 예정자 | Unity·HTML5·3D |
| vFabLab | Purdue | 장비 조작, 공정 순서 (비행 시뮬레이터 비유) | 실습 전 학생 | 웹·모바일 |
| CNF VR | Cornell | 12개 모듈(2027년 20개 목표) | 재학생·연구자 | VR·PC·태블릿 |

셋의 공통점: **"어떻게 하는가"를 가르친다.** 가운을 어떻게 입고, 장비를 어떤 순서로 조작하고, 공정을 어떻게 진행하는가.

성과 지표도 절차 숙달이다. Purdue는 "vFabLab으로 훈련한 학생이 실제 클린룸에서 소자를 제작했다"를 성과로 든다.

## 1-2. 우리는 「원인 진단」이다

**절차를 아는 것과 문제를 푸는 것은 다른 능력이다.**

| | 절차 훈련 (경쟁군) | **원인 진단 (Virtual Fab)** |
|---|---|---|
| 질문 | 어떻게 하는가 | **왜 이렇게 됐는가** |
| 정답 | 매뉴얼에 있다 | **데이터에서 찾아야 한다** |
| 실패 | 순서를 틀림 | **잘못된 결론에 도달함** |
| 반복 | 숙달될수록 빨라짐 | **매번 다른 원인** |
| 대상 | 클린룸 투입 예정자 | **취업 준비생** |
| 목적 | 사고 예방 | **면접에서 말할 경험** |

**대상이 다르다는 점이 핵심이다.** 경쟁군은 이미 합격해 실습을 앞둔 사람을 훈련한다.
우리는 **아직 들어가지 못한 사람**이 대상이며, 산출물은 소자가 아니라 **면접 증거물**이다.

## 1-3. 포지셔닝 문장

> **"가상 팹 최초"가 아니다. 한국 취업준비생을 위한 불량 해결 RPG다.**

이 문장이 제안서·마케팅·제품 설계의 기준선이다. 경쟁군과 같은 축에서 싸우지 않는다.

# 2. 무엇을 바꾸는가 — 「공정 체험」에서 「불량 해결 RPG」로

## 2-1. v1의 구조적 한계

v1은 6단계 선형 클릭이다. 학생은 "체험"할 뿐 **선택의 무게를 느끼지 않는다.**

- 예산 80·시간 60이 있지만 사실상 제약이 아니다
- 실패해도 잃는 것이 없다 (재시작 무료)
- 다음에 무엇이 나올지 내 선택이 바꾸지 않는다

## 2-2. RPG로 만드는 3요소

### ① 자원이 진짜로 부족해야 한다

| 자원 | 의미 | 설계 |
|---|---|---|
| **예산** | 분석 장비 사용료 | 정답 경로를 모두 밟으면 **초과되도록** 설정 |
| **시간** | 납기 압박 | 매 턴 소모, 초과 시 **양산 라인 정지 페널티** |
| **신뢰도** | 팀장·유관부서 신뢰 | 근거 없이 주장하면 하락, 하락하면 **추가 분석 요청 거부됨** |

**세 자원이 서로 상충해야 한다.** 시간을 아끼면 예산을 쓰고, 예산을 아끼면 신뢰도를 잃는다.

### ② 실패가 이야기가 되어야 한다

현재는 실패해도 점수만 깎인다. 바꾼다.

| 실패 유형 | 결과 |
|---|---|
| 미끼 장비를 원인으로 지목 | 해당 장비 정지 → **생산 차질 발생** → 잘못된 조치임이 드러남 |
| 검증 없이 Recipe 변경 | 다음 Lot에서 **다른 이상 발생** |
| 파괴분석 남용 | 웨이퍼 소진 → **재측정 불가** |
| 시간 초과 | 상급자가 임의 판단 → **본인 이름이 보고서에서 빠짐** |

**실패 화면에서 정답을 알려주지 않는다.** 대신 "무엇을 놓쳤는지" 데이터를 다시 보여준다.

### ③ 캐릭터와 서사

- 플레이어: 입사 3개월차 공정기술 엔지니어
- NPC: 팀장(압박), 설비팀(협조 요청 대상), 품질팀(반박), AI 멘토(질문만 함)
- 대화 선택지가 신뢰도에 영향

**NPC는 정답을 알려주지 않는다.** 팀장은 재촉하고, 설비팀은 자기 장비를 방어하고, 품질팀은 근거를 요구한다.

# 3. 기술 전환 — Three.js → React + Phaser 아이소메트릭

## 3-1. 왜 바꾸는가

| 항목 | Three.js (현행) | **Phaser 아이소메트릭 (제안)** |
|---|---|---|
| 렌더링 | WebGL 3D 실시간 | 2D 스프라이트 합성 |
| 모바일 GPU 부하 | 높음 | **낮음** |
| 초기 로딩 | 3D 에셋·셰이더 컴파일 | **이미지 아틀라스 1장** |
| 저사양 노트북 | 프레임 드랍 위험 | **안정적** |
| 개발 속도 | 3D 좌표·조명·카메라 | **타일 배치** |
| 아트 확보 | 3D 모델링 필요 | **2D 일러스트로 충분** |

**대상이 취업준비생이다.** 고사양 GPU가 없는 노트북·모바일이 다수다.
경쟁군(Cornell VR)이 VR 헤드셋을 요구하는 것과 반대로 가야 한다.

## 3-2. 성능 목표 (측정 가능한 기준)

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 초기 로딩 (LCP) | **≤ 2.5초** | Lighthouse, 4G 스로틀 |
| 총 전송량 | **≤ 3MB** | Network 탭, gzip 후 |
| 프레임레이트 | **≥ 50fps** | 중급 노트북(내장그래픽) |
| 모바일 프레임 | **≥ 30fps** | 중급 안드로이드 |
| 상호작용 지연 (INP) | **≤ 200ms** | Lighthouse |
| 메모리 | **≤ 250MB** | Chrome Task Manager |

**Lighthouse 성능 점수 ≥ 90을 검수 조건으로 고정한다.**

## 3-3. 단계별 기술 로드맵

```
1단계 (지금)  React + Phaser 3 아이소메트릭 2D
              → 게임 루프·자원·서사 완성. 성능 확보.

2단계 (검증 후) 특정 씬만 React Three Fiber 부분 도입
              → 웨이퍼 맵 3D 회전 등 3D가 실익 있는 곳만

3단계 (확장)   3인칭 캐릭터 이동
              → 팹 내부를 걸어다니며 장비 접근
```

**2단계를 1단계와 동시에 하지 마라.** v1의 실패가 그것이었다.

# 4. 화면 설계

## 4-1. 메인 화면 — 아이소메트릭 팹

```
┌─────────────────────────────────────────┐
│ [자원바] 예산 ▓▓▓░ 62 · 시간 ▓▓░░ 38 · 신뢰 ▓▓▓▓ 74 │
├─────────────────────────────────────────┤
│                                         │
│      ▨ 포토       ▨ 식각      ▨ 계측     │
│         ▲            ▲          ▲       │
│      [!]          [ ]         [ ]       │
│                                         │
│         ▨ 증착       ▨ 분석실            │
│            ▲            ▲               │
│                                         │
├─────────────────────────────────────────┤
│ 💬 팀장: "오후까지 원인 못 찾으면 라인 세운다"  │
└─────────────────────────────────────────┘
```

- 아이소메트릭 타일 위에 장비 배치
- `[!]` 표시 = 이상 발생 장비 (조사 가능)
- 장비 클릭 → 해당 데이터·분석 인터페이스 진입
- 하단 대화창에 NPC 대사

## 4-2. 데이터 분석 화면 (핵심)

**이 화면이 상품의 본체다.** 여기서 학생이 실제로 판단한다.

```
┌──────────────────┬──────────────────────┐
│  웨이퍼 맵        │  그룹핑 축            │
│  (색=CD, 클릭 가능)│  ○ 장비  ○ Lot       │
│                  │  ○ 반경  ○ 시간       │
│      ● ● ●       │                      │
│    ● ○ ○ ○ ●     │  집계 방식            │
│   ● ○ ◐ ◐ ○ ●    │  ○ 평균 ○ 중앙값      │
│    ● ○ ○ ○ ●     │  ○ 표준편차 ○ p95     │
│      ● ● ●       │                      │
│                  │  [그래프 그리기]       │
├──────────────────┴──────────────────────┤
│  [박스플롯] [산점도] [시계열]  [CSV 받기]   │
└─────────────────────────────────────────┘
```

**필수**: 반경(radius)을 구간으로 묶는 기능. 이게 없으면 가장자리 이상을 발견할 수 없다.

## 4-3. AI 멘토 — 하나의 근거 제한형

개발에는 멀티에이전트를 쓰되 **학생이 만나는 AI는 하나다.**

| 원칙 | 구현 |
|---|---|
| 정답을 말하지 않는다 | 원인 장비명·수치를 응답에서 필터링 |
| 질문만 한다 | 출력 형식을 "질문 1개"로 고정 |
| 근거를 요구한다 | "그 판단의 근거 데이터는?" 형태 |
| 초안임을 표시 | `AI 초안 — 검증 필요` 라벨 상시 표시 |

**응답 지연 대응**: 현재 40~60초는 수업에서 치명적이다.

- 자주 나오는 질문 유형 **10종을 사전 생성해 캐시**
- 캐시 미스 시에만 실시간 호출
- 호출 중에는 **검증 프레임(코드 생성)을 먼저 표시**해 대기를 체감하지 않게 함
- 목표: **체감 응답 3초 이내**

# 5. 게임 루프 재설계

## 5-1. 턴 구조

```
[상황 제시] → [조사 선택] → [자원 소모] → [결과 확인] → [판단 입력]
     ↑                                                      │
     └──────────────── 신뢰도 변화 ─────────────────────────┘
```

한 시나리오 = **8~12턴**, 20~30분.

## 5-2. 조사 행동과 비용

| 행동 | 예산 | 시간 | 신뢰도 | 비고 |
|---|---|---|---|---|
| 데이터 재집계 | 0 | 2 | 0 | 무제한, 시간만 소모 |
| 광학 측정 | 4 | 3 | 0 | 비파괴 |
| SEM | 15 | 10 | 0 | 비파괴 |
| FIB-SEM | 35 | 25 | 0 | **웨이퍼 소진** |
| TEM | 50 | 40 | 0 | **웨이퍼 소진** |
| 설비팀 협조 요청 | 0 | 5 | −10 | 근거 없으면 거절 |
| 팀장 보고 | 0 | 2 | ±20 | 근거 품질에 따라 |
| 라인 정지 요청 | 0 | 0 | −30 | 오판 시 큰 페널티 |

**예산 80·시간 60으로는 모든 분석을 할 수 없다.** 반드시 포기해야 한다.

## 5-3. 엔딩 분기

| 엔딩 | 조건 |
|---|---|
| **원인 규명·최소 손실** | 진짜 원인 지목 + 자원 여유 + 신뢰도 유지 |
| **원인 규명·과다 비용** | 정답이지만 자원 소진 |
| **오판 후 정정** | 미끼 지목 → 결과 확인 → 재조사로 정정 |
| **오판 확정** | 미끼를 원인으로 최종 보고 |
| **시간 초과** | 상급자 임의 판단, 본인 기여 없음 |

**5종 엔딩 모두 면접 PT가 생성된다.** 실패해도 "무엇을 배웠는가"가 남는다.

# 6. 콘텐츠 구성

## 6-1. 시나리오 3종

| # | 제목 | 원인 구조 | 함정 |
|---|---|---|---|
| 1 | **사라진 선폭의 비밀** | 특정 장비의 가장자리 이상 | 장비 평균 비교 시 미끼가 1위 |
| 2 | **새벽에만 생기는 결함** | 시간대 의존 (챔버 컨디션) | 전체 평균으로는 안 보임 |
| 3 | **측정기가 거짓말한다** | 측정 시스템 오차 | 공정이 아니라 **계측이 원인** |

**시나리오 3이 가장 어렵다.** 학생은 공정을 의심하지만 답은 측정기에 있다.

## 6-2. 난이도

| | 초급 | 중급 | 고급 |
|---|---|---|---|
| 자원 | 여유 | 빠듯 | 부족 |
| 힌트 | 분석 축 제안 | 없음 | 없음 |
| 미끼 | 1개 | 2개 | 2개 + 데이터 품질 문제 |
| NPC 압박 | 약함 | 보통 | 강함 |

# 9. 금지사항

- 경쟁군(UC Davis·Purdue·Cornell)의 **절차 훈련 영역으로 들어가지 마라.** 가운 착용·장비 조작 순서는 우리 상품이 아니다.
- 실제 기업의 팹 배치·UI·Spec·데이터를 복제하지 마라.
- **P0-1 이전에 P0-2(그래픽)에 손대지 마라.** v1에서 이미 반복한 실수다.
- AI 멘토가 원인 장비명이나 정답 수치를 말하지 않도록 출력 필터를 반드시 둔다.
- 3D(R3F)는 P3다. 1단계에서 병행하지 마라.
