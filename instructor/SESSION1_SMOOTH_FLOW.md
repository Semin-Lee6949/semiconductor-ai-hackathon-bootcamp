# 1강 120분 매끄러운 진행표

## 강의의 한 줄 서사

> 현장 질문을 받는다 → 데이터가 틀릴 수 있음을 확인한다 → 도구를 설치한다 → noisy CSV를 통계와 그래프로 감사한다 → AI에게 검증 기준을 주고 최소 구현한다 → 배포한다 → 자신의 프로젝트 질문으로 전환한다.

모든 설명은 앞 단계에서 나온 결과를 다음 단계의 이유로 사용합니다. 통계 이론, AI 사용법, Git, 시각화를 별도 과목처럼 분리하지 않습니다.

## 시작 전 필수조건

20명이 설치부터 시작하면서 120분 안에 배포까지 가려면 다음은 수업 전에 끝나 있어야 합니다.

- GitHub 계정과 Claude·GPT·Gemini 중 주 AI 하나의 로그인
- Claude·GPT 사용자의 비상용 Gemini 또는 Antigravity 로그인
- 14:00 이후 Claude·GPT 사용량 보존 공지
- Windows/macOS 인원 조사
- 설치파일 또는 공식 설치 URL 준비
- Python 패키지 wheel cache 또는 완성 PNG 백업
- 4개 조 × 5명 좌석·번호 배정
- 보조강사 1명
- `student/00_PROBLEM_DISCOVERY_QUESTIONNAIRE.md` 사전 배포와 10분 1차 작성

계정 생성까지 수업에서 시작하면 통계·시각화 실습 시간이 사라집니다. 계정은 사전 준비, 프로그램은 수업에서 단계별 설치가 원칙입니다.

## 분 단위 진행

### 0~8분 — 문제로 시작

화면:

- 원본 CMP 데이터 첫 10행
- 질문: “수율 평균이 내려갔다. 공정 변화인가, 데이터 변화인가?”
- 수강생 질문지에서 `사용자·반복 관측·결정` 한 문장 2개 공유

설명:

- 오늘의 결과물 4개
- 실제 회사자료 사용 금지
- Telegram `✅/🟡/🔴` 규칙

하지 않을 것:

- 강사 이력 소개를 길게 하지 않는다.
- AI 기능 목록부터 설명하지 않는다.

연결 멘트:

> “평균을 계산하기 전에 평균을 만든 데이터가 믿을 만한지 확인해야 합니다.”

### 8~18분 — 결측·이상치의 의미

화면:

- 결측 56개
- 완전 중복 5개
- Tool별 표본 426/191/114/74
- 극단값이 포함된 산점도

질문:

1. 결측행을 모두 지우면 어떤 조건이 사라질 수 있는가?
2. Down Force 극단점은 단위 오류인가, 실제 Recipe인가?
3. T01 표본이 절반 이상이면 전체 평균은 누구를 대표하는가?

핵심:

- 결측은 발생 메커니즘과 위치가 중요하다.
- 이상치는 자동 삭제 대상이 아니라 검토 후보이다.
- 처리 전후 결론과 Holdout 성능을 비교해야 한다.

연결 멘트:

> “이제 같은 검사를 여러분 PC에서 재현하기 위해 도구를 설치합니다.”

### 18~38분 — 설치

강사는 Telegram 메시지를 하나씩 보냅니다.

1. VS Code
2. Git
3. Python
4. Claude·GPT·Gemini 중 주 AI 하나 확인
5. 비상 Gemini 또는 Antigravity 로그인
6. 버전과 READY 확인

화면에는 현재 설치할 도구 하나만 띄웁니다. 다음 명령을 미리 보여주지 않습니다.

통과:

- 15명 이상 기본 도구와 선택한 AI 로그인, 비상 Gemini 준비
- `code` 명령만 실패하면 VS Code 직접 실행으로 통과

연결 멘트:

> “도구 설치가 목적이 아닙니다. 이제 같은 데이터와 같은 명령으로 결과를 재현합니다.”

### 38~52분 — 로그인·Clone·READY

순서:

1. 선택한 AI 로그인과 사용 가능 여부 확인
2. Git 사용자 이름·이메일
3. 개인 저장소 생성·Clone
4. `student_preflight.py`

통과:

- `READY: core environment checks passed`

15명 완료 후 다음 단계로 이동하고 미완료자는 보조강사가 복구합니다.

Claude·GPT에서 한도 메시지가 나오면 원인 분석에 시간을 쓰지 않고 `🟣 한도`를 남긴 뒤 Gemini → 페어 → 로컬 스크립트 순으로 즉시 전환합니다.

연결 멘트:

> “환경 차이를 제거했습니다. 이제 모델을 만들기 전에 데이터가 어떤 방식으로 거짓말하는지 확인합니다.”

### 52~67분 — 통계적 데이터 감사

화면을 다음 순서로 고정합니다.

1. `shape` — 분석 대상의 크기
2. `dtypes`와 단위 — 숫자처럼 보이는 문자열·혼합 단위
3. `isna().sum()` — 결측 규모
4. `duplicated().sum()` — 중복
5. 분위수·IQR — 극단값 후보
6. Tool·Lot·시간별 `count` — 표본 편중

강조:

- 평균보다 표본 수를 먼저 본다.
- 결측 비율 하나보다 발생 위치를 본다.
- IQR 플래그는 삭제 명령이 아니다.
- 원본은 수정하지 않는다.

연결 멘트:

> “숫자 표로 규모를 알았지만 발생 패턴은 잘 보이지 않습니다. 질문에 맞는 그래프로 바꾸겠습니다.”

### 67~80분 — 그래프 갤러리

두 사이트를 나란히 엽니다.

- [seaborn Example Gallery](https://seaborn.pydata.org/examples/index.html)
- [ggplot2 Reference](https://ggplot2.tidyverse.org/reference/index.html)

보여줄 것은 다섯 종류뿐입니다.

1. Histogram — 분포
2. Box + points — Tool 비교
3. Scatter — 두 변수 관계
4. Line — 시간 Drift
5. Heatmap — 결측·상관

ggplot2와 seaborn의 문법 차이를 강의하지 않습니다. 둘 다 데이터, 변수 역할, 표시방법, 그룹/Facet을 조합한다는 공통 구조만 설명합니다.

연결 멘트:

> “예쁜 그림을 고르는 것이 아니라, 지금 검증할 질문에 답하는 그림을 고릅니다.”

### 80~95분 — seaborn 직접 실습

수강생은 `data_quality_visualization_demo.py`를 실행합니다.

생성 순서:

1. 분포
2. Tool별 box + point
3. 공정 입력과 KPI 산점도
4. Run 순서 rolling median
5. 결측 위치 heatmap
6. 상관 heatmap

각 그래프에서 한 문장씩 말하게 합니다.

```text
관찰 사실:
가능한 설명:
대안 설명:
추가 확인:
```

연결 멘트:

> “이제 AI에게 차트를 그려 달라고 하지 않고, 방금 정한 질문·검증·완료 기준을 전달합니다.”

### 95~106분 — 선택한 Coding Agent의 최소 변경과 Git 증거

순서:

1. 저장소 규칙 읽기
2. 수정 전 성공 기준
3. 요청된 파일만 변경
4. 테스트·빌드
5. 사람이 `git diff` 확인
6. Commit·Push

연결 멘트:

> “AI가 만든 코드가 아니라, 질문·검증·수정 이력이 여러분의 역량 증거입니다.”

### 106~116분 — 웹앱과 Pages

1. 로컬 웹앱 실행
2. 입력 2개 변경
3. 결과·위험도 갱신 확인
4. Pages `main /docs`
5. 저장소·URL 제출

Pages가 지연되면 기다리지 않고 저장소 URL을 먼저 제출합니다.

연결 멘트:

> “공통 도구를 익혔으니 마지막은 모델 선택이 아니라 내 직무의 결정 선택입니다.”

### 116~120분 — 주제선정으로 넘기기

수강생은 수업 전 질문지를 다시 열고, 방금 배운 데이터 감사와 상관·대안 설명을 붙여 후보 2개를 적습니다.

결정:

최종 주제는 데이터 감사 후 확정합니다.

## 시간이 밀릴 때 줄이는 순서

1. Pages 배포 대기시간 — 저장소 URL부터 제출
2. Codex의 긴 설명 — 제공 프롬프트와 최소 변경만 실행
3. Gallery 예시 수 — 다섯 개를 세 개로 축소
4. 설치 실패자 전체 대기 — 보조강사·파트너·ZIP 우회

줄이지 않을 것:

- 보안 경계
- 결측·이상치·표본 편중 감사
- 그래프가 답할 질문
- 사람의 `git diff`와 테스트 확인
- 사용자 결정 중심 주제선정
